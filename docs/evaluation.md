# 评测方法与成本口径

本文解释[结果报告](../results/REPORT.md)。评测脚本、内部数据集和逐条输出不随项目发布。

## 数据边界

评测使用内部保留数据，只发布聚合指标。prompt、样本 ID、划分流程、来源关系和逐条输出均不公开。参考列表示一次外部模型参考结果，用于内部对照，不是公开 benchmark 标签，也不表示两个模型能力等价。

## 模型配置

发布评测使用 BF16 合并权重、带项目补丁的 vLLM 0.22.1、ngram k=32、temperature=0.7、top_p=0.95、seed=42，最大输出 32768 token。每个实例使用一张 A100 SXM4 40GB，每次只处理一个请求。

模型输入只包含 system/user 消息，不会把参考答案发送给模型。冷启动和预热时间与请求计时分开；达到输出上限的请求仍计入聚合分母。

## 独立思考与任务协议

独立的 `reasoning_content` 或外层 thinking 通道不计入评测。任务协议内部的 `<aix_analysis>`、`<item_analysis>`、决策、替换文本和摘要全部保留。独立 thinking 不在公开聚合中单独计量。

## 质量指标

规则综合分由以下六项构成：

| 组件 | 权重 | 衡量内容 |
|---|---:|---|
| 任务合规性 | 10% | 格式、决策覆盖和任务执行 |
| 摘要结构 | 20% | 必需章节与信息密度 |
| 剪枝策略 | 15% | 合法且有效的保留与工具结果替换 |
| 压缩效率 | 15% | 保留比例与压缩强度 |
| 信息保留 | 20% | 实体和关键修改信号是否有依据地保留 |
| 替换质量 | 20% | 缩短后的工具结果质量与覆盖度 |

这些是任务相关的规则指标，不是下游 coding 任务成功率或人工质量评分。

质量、格式、成功率和整体保留率都使用完整的内部评测集合分母。失败请求质量记为 0，保留率记为 1，表示未完成压缩。条件统计会单独保留自己的样本数。

模型质量保留率按规范化消息 JSON 计算；服务兜底按可见消息文本计算，两者分母不同，不能直接相减解释兜底收益。

## 服务回放

同一批模型输出会经过公开解析器、组装器和保留率兜底进行确定性回放。报告分别展示原始模型结果、兜底次数、最终保留率、工具配对完整性和摘要超预算情况。回放是确定性后处理，不会再次调用模型。

另有真实 OpenCode 两轮压缩联调和推理中取消请求验证。coding-model provider 在 OpenCode 测试中使用 测试替身，因此不代表完整 coding 任务成功率。

## 成本情景

### GPU 成本

```text
GPU 成本 = GPU 数量 × 每小时价格 × 推理秒数 / 3600
```

aiXcompact 使用实测请求耗时；小时价格只是公开租用情景，不是公司实际账单。表中展示 100%、50%、25% 利用率；不包含训练、税费、存储、启动摊销和运维成本。

DeepSeek 的公开部署基准与本项目负载不匹配，且缺少可用的对应 prefill/decode 分解。报告中的 DeepSeek GPU 费用是公开吞吐代理下的参考预算；表中节省百分比按 `1 − aiXcompact / DeepSeek` 计算，只比较该代理情景，不是同负载实测节省。

## 解码模式说明

合成样例显示普通解码与 ngram 文本存在差异，首次分歧来自相近的候选 token。未证明唯一成因，也不承诺逐 token 等价。完整质量与运行结果均直接使用 ngram 配置测量。

## 已公开证据

公开仓库仅保留[结果报告](../results/REPORT.md)及其中的聚合图表。价格日期、来源链接、验证范围和解码观察已汇总在报告中，不单独发布逐项 JSON 记录。

协议说明见[输入输出与兼容格式](protocol-and-data.md)。内部逐条记录和数据构造审计不会公开。
